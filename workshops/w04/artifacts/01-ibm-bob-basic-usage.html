三種模式一覽

拿到 SAST 報告後，正確的工作流程是依序切換三個模式，每個模式做它最擅長的事。

Ask

知識模式

閱讀代碼、理解報告、解釋概念。不會修改任何檔案，適合搞懂陌生程式庫或確認弱點根因。

讀懂代碼 解釋弱點 確認根因 查詢文件

權限：唯讀。不寫入本地檔案，不執行命令。

Plan

規劃模式

分析修補方案、評估影響範圍、列出步驟。聚焦「做什麼」，在動手前確認方向正確。

修補方案設計 影響分析 任務拆解 風險評估

權限：可讀取檔案，僅輸出計畫文字，不直接執行修改。

Agent

執行模式

撰寫代碼、修改檔案、執行命令。在規劃確認後切換，讓 Bob 自動完成修補。

修改代碼 建立檔案 執行命令 產出 Diff

權限：完整讀寫，可呼叫工具、執行 Shell 命令。

實際演練

以上方 Checkmarx 報告為起點，依序示範三個模式的正確用法。

Step 1 — Ask 模式

搞懂弱點報告在做什麼，以及與程式碼的關聯

拿到 SAST 報告，第一步不是馬上動手修。先用 Ask 模式，直接把報告檔案 CX-2025-0714-001.md 丟給 Bob，讓它讀懂弱點內容、確認問題屬實、理解財務衝擊。

Prompt — Ask 模式 
@CX-2025-0714-001.md 這是資安剛送來的 SAST 報告，幫我確認問題是否屬實，以及實際的財務衝擊是什麼。
Bob 會回答的內容方向
✓ 讀取 BKTRXN.cbl → 逐步追蹤轉帳流程 → 確認 3200-UPDATE-TARGET-BAL 段落存在但缺少 PERFORM 呼叫 ✓ 說明：每次轉帳，來源帳戶金額減少，目標帳戶金額不變，資金「消失」在系統中 ✓ 說明財務衝擊：若轉帳金額為 $100,000，客戶帳戶損失 $100,000，對方帳戶未收到 ✓ 不修改任何檔案

Step 2 — Plan 模式

規劃弱點修補與問題修正方案

Ask 模式已確認弱點屬實，也理解了財務衝擊。現在切換 Plan 模式，在動手修改程式碼之前，先讓 Bob 評估完整的修補範圍、邊界條件，以及可能影響到的其他模組。

Prompt — Plan 模式 
好，問題確認了。請規劃修補方案，包含修改步驟、邊界條件處理、以及失敗時如何回滾。
Bob 會回答的內容方向
✓ 讀取 BKTRXN.cbl + BKDB2.cbl → 對照可用的 DB2 操作碼（SELA / UPDB） ✓ 列出修補步驟：① 查詢目標帳戶（SELA）→ ② 驗證帳戶存在且狀態正常 → ③ 計算新餘額 → ④ 呼叫 3200-UPDATE-TARGET-BAL ✓ 說明回滾策略：目標帳戶更新失敗時，需還原來源帳戶餘額 ✓ 不修改任何檔案

Step 3 — Agent 模式

執行弱點修補與問題修正

修補方案已在 Plan 模式確認。切換至 Agent 模式，Bob 會先透過 using-git-worktrees Skill 建立隔離分支，再修改 BKTRXN.cbl，補齊目標帳戶更新邏輯，並說明每一處變動與對應的 CWE-841 修補要求。

使用 Git Worktree 的好處 說明
保護主線分支 所有修改在獨立分支上進行，main / workshop/w04 不受影響，隨時可放棄該分支並重來。
乾淨的基線驗證 建立 worktree 後立即執行測試，確認起點是乾淨的。若修補後測試失敗，立刻能判斷是本次變更造成，而非既有問題。
多工並行 可同時在多個 worktree 中作業（例如一個修 CWE-841、另一個查看 main），共用同一份 Git 物件儲存區，無需重複 clone。
易於 Code Review 修補完成後直接從隔離分支開 PR，Diff 精準只含本次修補，不夾雜其他未提交變更，方便資安團隊審查。
降低誤操作風險 AI Agent 直接在隔離目錄寫入，即使操作出錯也不會污染工作區其他檔案；刪除 worktree 即完全還原。
Prompt — Agent 模式 
計畫沒問題，請執行。先用 using-git-worktrees 建好隔離分支再改。
Bob 會做的動作
✓ 啟用 using-git-worktrees Skill → 偵測是否已在 linked worktree → 建立隔離分支（如 fix/cwe-841） ✓ 讀取 BKTRXN.cbl + BKDB2.cbl → 定位 1000-PROCESS-TRANSFER ✓ 新增：查詢目標帳戶（SELA）→ 驗證帳戶狀態 → 計算新餘額 → 呼叫 3200-UPDATE-TARGET-BAL ✓ 新增：若目標帳戶更新失敗，呼叫 3100-UPDATE-SOURCE-BAL 還原來源帳戶 ✓ 在隔離分支上修改 BKTRXN.cbl 並輸出 Before / After Diff

Step 4 — Ask 模式

比較目前分支與 fix 分支（bktrxn-transfer-fix）的差異
