IBM Bob 進階功能設定

掌握三大模式後，本教材帶您深入 IBM Bob 的進階工具：內建 Slash Commands、Skills 技能擴充、MCP Server 連接、Bob Rules 行為規範，以及 .bobignore 檔案存取控管。

內建 Slash Commands

在 Bob 的對話輸入框輸入 /，即會彈出命令選單。

指令 說明
/init 掃描整個專案，自動產出 AGENTS.md 與各模式專屬的上下文檔案。LLM 是無狀態的，/init 讓 Bob 在每次對話開始時都能立即理解專案結構，無需重複說明。
/review 審查程式碼變更。支援多種用法：/review（審查本地未提交的變更）、/review <branch>（比對指定分支）、/review #<issue> --issue-coverage（驗證變更是否符合 GitHub Issue 要求）。會執行 Bug 偵測、安全性檢查、效能分析與風格一致性審查。

Skills 的使用

Skill 是一份可重複使用的工作流指引，告訴 Bob 在特定場景下應遵循哪些步驟與最佳實踐。在 Bob 的對話輸入框輸入 /，彈出的選單除了顯示內建命令（如 /init、/review）之外，也會列出所有已安裝的 Skills，可直接選取啟用。本專案已安裝下列兩個專案級 Skill：

Skill 名稱 用途說明
find-skills 協助探索並安裝 Agent Skill。當您詢問「有沒有可以做 X 的技能？」或「是否有 Skill 能幫我…」時，Bob 會透過此 Skill 搜尋技能生態系（skills.sh），評估安裝數與來源可信度後，提供安裝指令與說明。
using-git-worktrees 在開始功能開發或執行實作計劃前，確保工作在隔離的環境（isolated workspace）中進行。Skill 會優先偵測是否已在 linked worktree 中、其次使用平台原生工具，最後才 fallback 至手動 git worktree add，並自動處理目錄忽略與基線測試。來源：obra/superpowers。
💡

小技巧

在對話框輸入 / 再輸入 Skill 名稱即可直接啟用，例如輸入 /using-git-worktrees。

MCP Server 設定

MCP（Model Context Protocol）讓 Bob 連接外部工具與服務，擴展其原生能力。MCP Server 設定存放於 .bob/mcp.json，Bob 啟動時會自動載入。

本專案目前的 MCP 設定（.bob/mcp.json）：已連接 docs-mcp-server，使用 SSE 傳輸協定連接 http://localhost:6280/sse，讓 Bob 能透過本地文件伺服器存取專案相關技術文件。 
{
    "mcpServers": {
        "docs-mcp-server": {
            "type": "sse",
            "url": "http://localhost:6280/sse"
        }
    }
}

若您需要新增其他 MCP Server，只需將設定描述給 Bob，它便能協助您完成 .bob/mcp.json 的修改並驗證是否生效。

情境範例：請 Bob 新增 MCP Server（Agent 模式）
請幫我在 .bob/mcp.json 中新增一個名為 docs-mcp-server 的 MCP Server，使用 SSE 傳輸協定，連接 http://localhost:6280/sse。
預期 Bob 的回應方向
Bob 直接修改 .bob/mcp.json，加入新的 Server 設定，並說明如何驗證連線是否正常。
情境範例：透過 docs-mcp-server 查詢技術文件（Agent 模式）
使用 docs mcp server 查詢 spring boot 文件庫，提供設定多語系的 yaml 設定範例。
預期 Bob 的回應方向
Bob 透過 docs-mcp-server 搜尋 Spring Boot 文件庫，找到多語系（i18n）相關章節後，直接回傳 application.yml 中 spring.messages 的設定範例，例如指定 basename、encoding 與 fallback 策略，無需離開 IDE 或手動查閱官方文件。

Bob Rules（行為規範）

Bob Rules 是存放於 .bob/rules/ 資料夾中的 Markdown 檔案，Bob 會在每次對話開始時自動注入這些規則，無需在 Prompt 中重複說明。規則可以是：編碼風格、溝通語言、技術限制，或任何需要一致執行的工作守則。

規則範圍 說明與路徑
專案級（版本控管） .bob/rules/ — 適用於本專案，隨 Git 版控，團隊成員 clone 後即生效。
模式專屬 .bob/rules-agent/ 僅在 Agent 模式下注入，.bob/rules-ask/ 僅在 Ask 模式下注入，以此類推，可細粒度控制。
全域（個人設定） ~/.bob/rules/（macOS/Linux）— 適用於該使用者在所有專案中的 Bob 對話，不進入版控。

範例：本專案的 MCP Server 啟動規則

本專案的 .bob/rules/docs-mcp-server.md 就是一個實際的 Bob Rule 範例——它告訴 Bob：若 docs-mcp-server 連線失敗，應先執行啟動指令再繼續操作。

# .bob/rules/docs-mcp-server.md

# docs-mcp-server 啟動規則

若 `docs-mcp-server` MCP 伺服器尚未執行或連線失敗，請在繼續操作前執行以下指令啟動它：

```
npx @arabold/docs-mcp-server@latest
```

在終端機中執行此指令，並等待伺服器就緒後，再重試任何依賴它的工具呼叫。
💡

小技巧

也可以直接告訴 Bob：「請幫我在 .bob/rules/ 建立一個規則檔，要求你一律回應繁體中文並遵循這個專案的 COBOL 版本限制。」Bob 會自動建立內容正確的規則檔。

.bobignore 檔案存取控管

.bobignore 讓您指定 Bob 不應存取或修改的檔案與目錄，語法與 .gitignore 相同。這是保護敏感資訊、防止誤改已產出檔案的重要機制。Bob 會即時監看此檔案，任何變更立即生效。

使用場景 .bobignore 範例內容
保護環境變數與密鑰 .env
secrets/
*.key
config/credentials.json
排除大型二進位或已產出檔案 output/
*.class
build/
dist/
限制 Bob 只操作特定目錄 （搭配 AGENTS.md 說明哪些目錄是主要工作範圍） 
# 建立 .bobignore 範例（專案根目錄）
cat > .bobignore <<'EOF'
# 敏感設定
.env
secrets/
*.key
config/credentials.json

# 已產出的檔案（不需要 Bob 修改）
output/
docs/

# 編譯產物
*.class
build/
EOF
注意事項：.bobignore 僅對 Bob 透過工具存取檔案的行為有效，不構成系統層級的沙箱隔離。敏感資料仍應搭配 Git 的 .gitignore 與適當的存取控管機制一起保護。
