工作坊教材 · COBOL 傳承

用 IBM Bob 解讀、文件化與傳承 COBOL 程式

本單元以 IBM cics-genapp 保險核心交易系統的 COBOL 原始碼為素材，帶你依序體驗 Ask、Plan、Agent 三種模式：從認識陌生專案，到產出技術文件，最後在隔離的 Git worktree 中新增水災險功能。全程在本機進行，不需要 Mainframe 環境。

⚠️ 本 repo 的 COBOL 版本為 ACU COBOL（ACUCOBOL-GT / Rocket extend），並非原始 IBM z/OS COBOL。程式已從 CICS 環境轉置，以標準 CALL/GOBACK 取代 CICS 指令，不需要 Mainframe 或 CICS 環境。但本 repo 共 27 支程式中，9 支 DB2 存取層程式（LGxDB01）含有 EXEC SQL 語句，需要 DB2 runtime 才能執行；業務邏輯層（LGxPOL01）與 VSAM 存取層（LGxVS01）則可在本機直接用 GnuCOBOL 進行語法驗證。

認識練習素材

練習素材已包含在本 repo 中。以 IBM Bob 開啟 repo 根目錄後即可直接開始。

COBOL/          ← COBOL 原始程式（27 支 .cbl）
COPY/           ← Copybook 共用資料結構
DOC-SPEC.md     ← 文件框架規格（任務二使用）
DESIGN.md       ← HTML 設計規範（任務二使用）
plans/          ← Planning 階段產出的計畫存放位置
docs/           ← 任務二產出的五份 .md 文件
output/         ← 任務二產出的 HTML

任務二會將整個專案整理為以下五份模組文件：

技術文件 模組 涵蓋內容
doc-customer.md 客戶管理 客戶新增、查詢、更新相關程式與資料流
doc-policy-add-inq.md 保單新增與查詢 保單建立、查詢與相關資料存取
doc-policy-upd-del.md 保單更新與刪除 DB2、VSAM 更新及刪除流程
doc-infra-tools.md 基礎設施與工具 系統支援、資料庫與共用工具程式
doc-copybooks.md 共用 Copybook 共用通訊區與保單資料結構

三個實作任務

假設你剛拿到這份程式碼庫，對 COBOL 也不熟悉。接下來請依序體驗 Ask → Plan → Agent 三種模式，從建立系統全貌，到完成文件，最後安全地實作新功能。

任務一：Onboarding — 用 Ask Mode 認識陌生專案

切換到 Ask 模式。不需要先讀任何程式碼，直接用自然語言問 Bob。

Prompt 1-A：認識系統
這是一個我完全陌生的專案，請幫我認識這個系統是做什麼的、目錄怎麼組織，以及我該從哪裡開始看。
預期 Bob 的回應方向
Bob 會主動探索工作區，說明 COBOL/、COPY/、規格文件的用途，並給出適合新手的閱讀路徑。
Prompt 1-B：理解業務模組
請用繁體中文整理這個系統的主要業務功能與程式分組，說明各組如何互相合作。
預期 Bob 的回應方向
Bob 會把 27 支程式歸納成業務模組（客戶管理、保單新增查詢、保單更新刪除、基礎設施、共用 Copybook），協助你從整體架構而非個別檔案開始理解。

任務二：Documentation — 從程式碼產出 HTML 技術文件

先切換到 Plan 模式建立執行計畫，再切換到 Agent 模式依計畫產出五份 Markdown 文件並整合成 HTML。

DOC-SPEC.md 是文件框架規格，DESIGN.md 是 HTML 設計規範。不需要先讀這兩份文件，Bob 會在規劃與執行時參照它們。
Prompt 2-A（Plan Mode）：建立文件計畫
請閱讀 DOC-SPEC.md 並分析 COBOL/ 與 COPY/，替這個專案規劃五份繁體中文技術文件的產出計畫。計畫需涵蓋各文件的程式範圍、章節結構、Mermaid 圖表需求與驗收標準，以及完整的執行步驟：依 DOC-SPEC.md 產出五份繁體中文Markdown技術文件存到docs/、依 DESIGN.md 整合成 HTML存到output/、完成後驗證所有 Mermaid 圖表語法並自動修正錯誤。計畫儲存到 plans/。
預期 Bob 的回應方向
Bob 會盤點所有程式與 Copybook，決定五份文件的邊界，規劃從原始碼分析、Markdown 產出、HTML 整合到圖表驗證的完整步驟，存成計畫檔案。
Prompt 2-B（Agent Mode）：執行文件計畫
請讀取剛才的文件撰寫計畫並依計畫執行。
預期 Bob 的回應方向
Bob 依計畫逐步完成：分析原始碼、產出五份 Markdown 文件至 docs/、整合成 HTML 至 output/，最後掃描並修正所有 Mermaid 圖表語法錯誤。

任務三：Feature Development — 使用 Worktree 新增水災險

同樣分成 Plan → Agent 兩階段。Bob 會先分析既有險種的實作方式、擬定計畫，再於獨立的 Git worktree 中執行，確保目前工作目錄不受影響。

為什麼使用 worktree？ Worktree 會建立獨立的工作目錄與分支，讓新功能的開發與原始碼完全隔離，即使實作尚未完成，主分支也不會被修改。
Prompt 3-A（Plan Mode）：規劃水災險
我想新增「水災險」險種。請先不要修改程式碼，分析現有險種的完整實作（資料結構、保單 CRUD、資料存取），找出影響範圍，並建立實作計畫。計畫需涵蓋資料定義、程式變更、測試方式與驗收標準，以及完整的執行步驟：建立獨立的 Git worktree 與功能分支、所有變更只在 worktree 中進行、完成後執行驗收項目並整理摘要。計畫存到 plans/。
預期 Bob 的回應方向
Bob 會追蹤現有險種在 Copybook、業務程式、資料存取程式之間的關聯，列出水災險的完整影響範圍，並把 worktree 建立、實作、測試與驗收的完整步驟納入計畫。
Prompt 3-B（Agent Mode）：在 Worktree 中實作
請讀取剛才的水災險實作計畫並依計畫執行。
預期 Bob 的回應方向
Bob 依計畫逐步完成：建立隔離的 worktree 與功能分支，在其中實作水災險的資料結構與 CRUD 功能，執行驗收項目，整理摘要。原工作目錄維持不變。

完成！您已走過理解、文件化與功能開發的完整流程

三個任務結束後，您體驗了用 Ask Mode 認識陌生專案、用 Plan + Agent Mode 產出技術文件，以及透過 worktree 安全地實作新功能。
