第三章：新增客戶（ADD Customer）

LGACUS01 — 業務邏輯層

ACUCOBOL-GT 特性 A：$IF/$SET/$END 條件編譯（手冊 p.30-34）

詐欺檢查模式控制 $IF FRAUD-COBOL-MODE 控制詐欺檢查的實作路徑：
● 已定義：純 COBOL 版本 — 檢查手機號碼長度 >= 7
● 預留介面：可擴充為外部服務（原為 CALL JAVA USING LGACJV01）

Java Interop 移除說明

⚠ Java Interop 已完全移除 原始 IBM COBOL 程式包含兩處 CALL JAVA，轉置後全部移除：
原 CALL JAVA功能轉置後處理
LGACJV01手機號碼詐欺檢查改為純 COBOL 長度檢查（>= 7 位）
LGACJV02郵遞區號格式檢查（Java 版）改用 CHECK-FIRST-COBOL 段落（原已存在的備選版本），CHECK-FIRST-JAVA 段落整個移除

關鍵 Level 78 常數

名稱值說明
WS-CA-HEADER-LEN18客戶 COMMAREA 最小標頭長度（比保單版 28 更小）

程式流程

  1. ACCEPT FROM ENVIRONMENT — 取得執行期識別資訊
  2. 驗證 COMMAREA 存在與長度（>= 18）
  3. 執行 CHECK-FIRST-COBOL（郵遞區號驗證）
  4. $IF FRAUD-COBOL-MODE：手機號碼長度 >= 7 驗證
  5. CALL 'LGACDB01' USING BY REFERENCE DFHCOMMAREA RETURNING WS-DB-RETURN-CODE
  6. GOBACK

LGACDB01 — DB2 存取層

IS EXTERNAL 客戶流水號機制（特性 G，手冊 p.90） 原始 z/OS 使用 EXEC CICS Get Counter(GENACUSTNUM)，轉置後改為 IS EXTERNAL 共用計數區。
由 LGSETUP 初始化，LGACDB01 讀取後遞增寫回。若初始值 = 0 則視為未初始化。

第四章：查詢客戶（INQ Customer）

LGICDB01 — DB2 存取層

⚠ 已知行為：CA-DOB(1:1) 被強制覆寫為 '3' GET-CUSTOMER-INFO 段落在 SQL SELECT 執行後，CA-DOB(1:1) 會被強制覆寫為字元 '3'（維持與 z/OS 生產系統的行為一致性）。

下游使用注意：若需使用出生日期，請使用 CA-DOB(2:9) 取得原始值，而非 CA-DOB。
⚠ 原始程式 ERROR-MSG 程式名誤植 原始 IBM 版本 EM-PROG 填入 'LGICUS01' 而非 'LGICDB01'，轉置版本已更正。

第六章：批次客戶匯入（NEWCUST）

項目內容
Program-IDNEWCUST
程式類型獨立批次程式（無 DFHCOMMAREA，無 CICS 環境需求）
功能從循序輸入檔讀取客戶資料，批次 INSERT 進 DB2 CUSTOMER
輸入檔路徑環境變數 INFILE 指定
記錄長度140 bytes

AcuSQL 兩階段編譯流程

# 步驟一：AcuSQL 預處理
acusql NEWCUST.cbl NEWCUST.cbl.i

# 步驟二：ACUCOBOL-GT 編譯
ccbl32 -Da4 NEWCUST.cbl.i

# 執行
export INFILE=/data/newcust.dat
acurun NEWCUST

轉置說明

原始 IBM COBOL轉置後
EXEC SQL INCLUDE CUSTOMERCOPY "CUSTOMER.def"（AcuSQL 展開為 DCLCUSTOMER）
EXEC SQL INCLUDE SQLCACOPY "sqlca.def"
RECORDING MODE IS F移除（ACUCOBOL 不支援 z/OS 特定子句）
LABEL RECORDS STANDARD移除
BLOCK CONTAINS 0 RECORDS移除
