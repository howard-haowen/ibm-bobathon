團隊分工計劃

讓你了解如何在一天內有效分工完成 MVP、透過 IBM Bob AI 輔助完成任務，以及如何讓 Bob 幫你操作 Git。

核心前提

整個計劃的設計基礎

每人僅有 40 BobCoins，且無法共用。所有人都透過 IBM Bob AI 完成分配到的任務。技術背景差異大：1–2 人有程式背景，其餘幾乎無開發經驗——但無程式經驗的成員同樣能透過 Bob 貢獻高品質成果。

設計原則

  • 一天時間有限，完成 MVP 比追求完美更重要
  • 選題確認與 GitHub 建置是全隊共同任務，技術成員協助非技術成員完成
  • 後續任務依個人強項分工，每個角色都有明確的 Bob 使用方式
  • 每人的 BobCoins 獨立計算，問 Bob 前先想清楚要什麼

各角色任務說明

每個角色的目標與具體產出

技術開發

打造可以展示的 MVP

核心原則：先讓它「能跑」，再讓它「好看」。

  • ✅ 一定要完成：3 個核心功能可在瀏覽器中展示
  • 🔵 時間允許再做：資料持久化、後端 API、使用者帳號
  • ❌ 今天不做：完美 UI、完整錯誤處理、效能優化

部署優先考慮 GitHub Pages（零設定、免費、數分鐘上線）。部署是 optional，有公開網址加分，沒有也不影響評審看到成果。

內容與研究

提供數據與用戶視角

不需要寫程式，但你的產出對評審非常關鍵。評審最在意：「這個問題真的存在嗎？規模多大？」找資料可參考 台灣公開資料入門指南 →

  • 問題背景文件（數據 + 現有解法的不足）
  • 用戶故事清單（誰會用這個工具、為什麼用）
  • 功能測試腳本（整合階段全隊用來測試的步驟清單）
視覺設計

給技術成員具體可操作的視覺規格

不需要用設計軟體。用 Bob 生成文字規格，技術成員可以直接把色碼套入程式碼。

  • 配色方案（主色、次要色、背景色，附色碼）
  • 核心頁面的布局說明（文字描述即可，不需畫圖）
  • 簡報視覺模板（Canva 或 Google Slides）
簡報 + 說故事

讓評審在 3 分鐘內理解「這個問題值得解決」

簡報的核心是故事，不是技術細節。讓評審先被問題打動，才會想看你的解法。

  • 8–10 頁評審簡報
  • 3 分鐘 Demo 腳本
  • 影響力論述（能幫助誰、改變什麼）

建議結構：封面 → 問題與規模 → 現有解法的不足 → 我們的解法 → Demo 展示 → 社會影響力 → 技術架構 → 團隊分工 → 未來規劃 → 結語

如何善用 BobCoins

每人 40 BobCoins，獨立計算、無法轉讓

有效使用的原則

  • 問 Bob 之前先想清楚「我要什麼輸出」，一次給完整背景，避免反覆提問
  • 生成的內容先用，不滿意再追問修改，不要每次都從頭重問
  • 技術開發任務通常比文件類任務需要更多來回，技術成員要特別注意節省
Git 是什麼？

你不需要記住任何指令，只需要理解「我在做什麼、為什麼這樣做」

想像你和隊友一起寫一份 Google Doc 報告，面臨幾個問題：有人刪掉了重要段落怎麼復原？兩人同時修改同一段落要保留誰的？Git 就是解決這些問題的工具。
追蹤每次修改
Google Doc 的「版本紀錄」，每次存檔都有紀錄
還原舊版本
遊戲的「讀取存檔」，可以回到任意時間點
多人同時開發
多人同時編輯不同段落，最後合併成一份
知道誰改了什麼
每次存檔都記名字，一目了然
幾個你需要知道的 Git 概念

理解這些名詞就夠了

Repository（Repo）＝ 專案的儲存庫

放所有程式碼和文件的地方。我們的 repo 放在 GitHub 上，所有人共用同一個。

Branch（分支）＝ 你的工作副本

想像 repo 是一棵樹，main 是主幹。每個人從主幹長出自己的分支來工作，做完後再合回主幹，不會互相干擾。

main（主幹） ├── feature/小明-簡報 ├── feature/小華-視覺設計 └── feature/阿強-技術開發

Commit（提交）＝ 存一個版本快照

每完成一個階段就 commit 一次，相當於按下「存檔」並寫下「我這次做了什麼」。

Push（推送）＝ 把存檔同步到 GitHub

Commit 只存在你自己的電腦。Push 才是上傳到 GitHub，讓隊友看到。

Pull Request（PR）＝ 申請合併到主幹

在自己的分支做完後，發一個 PR，讓技術 Lead 確認沒問題再合到 main。

讓 Bob 幫你操作 Git

非技術成員不需要自己下指令，告訴 Bob 你想做什麼

你想做的事告訴 Bob 這句話
建立自己的分支請幫我建立一個 branch，名稱是 feature/名字-角色
存檔（Commit）請幫我把目前的修改 commit，訊息是「新增：設計規格文件」
上傳到 GitHub（Push）請幫我把這個 branch push 到 GitHub
申請合併（PR）請幫我對 main branch 發一個 Pull Request
文件類任務（README 文案、測試腳本、視覺規格）也要透過 Bob commit 到 GitHub，讓你的貢獻在 repo 歷史上可見。評審通常會看 commit 歷史確認每人都有參與。
讓 Bob 操作 GitHub 的必要設定

Bob 要能代替你操作 GitHub，需要先完成一次 GitHub 認證

非技術成員

使用 gh CLI（最簡單）

請 Bob 在終端機安裝 gh CLI，再執行登入：

請幫我安裝 gh CLI，然後執行 gh auth login，引導我完成 GitHub 認證。

gh auth login 會進行互動式問答，依序選擇：

  • Account → GitHub.com
  • Protocol → HTTPS
  • Authenticate Git with your GitHub credentials → Yes
  • How to authenticate → Login with a web browser

瀏覽器開啟後登入 GitHub 並授權，完成後 git push 即可直接使用，不需要輸入密碼。

技術成員

使用 SSH Key

在 Bob 的終端機生成 SSH key，再將公鑰加入 GitHub：

請幫我生成一組 SSH key pair，並說明如何將公鑰加入 GitHub。

完成後，clone repo 時使用 SSH 網址（git@github.com:帳號/repo名稱.git），往後 push 不需要輸入密碼。

⚠️ 這個設定需要在 GitHub 建置階段前完成。每位成員在自己的電腦上各自設定一次，設定完成後請 Bob 確認能否成功連線到 repo，再開始正式工作。
Bob Prompt 快速卡片

直接複製以下 prompt，貼到 IBM Bob 對話框，Bob 會逐步引導你完成每項操作

組長任務（組長 = Repo 創建者）：創建團隊 GitHub Repo 並邀請所有組員為協作者
  • Step 1  確認並安裝 git 與 gh CLI
  • Step 2  執行 gh auth login，透過瀏覽器完成 GitHub 認證
  • Step 3  用 gh CLI 創建團隊 repo，並在 GitHub 網頁邀請所有組員為協作者
組長 Step 1  安裝 git 與 gh CLI 
請幫我確認系統是否已安裝 git 和 gh CLI。如果尚未安裝，請依照我的作業系統（macOS / Windows / Linux）給我安裝指令，並在安裝完成後執行以下指令確認版本：
git --version
gh --version
組長 Step 2  透過瀏覽器完成 GitHub 認證 
請幫我執行 gh auth login，並引導我完成以下選項：
- GitHub.com
- HTTPS
- Authenticate Git with your GitHub credentials → Yes
- Login with a web browser

瀏覽器開啟後，我會登入 GitHub 並授權。完成後請確認認證狀態：gh auth status
組長 Step 3  創建團隊 Repo 並邀請組員 
請幫我用 gh CLI 創建一個新的 GitHub repo，設定為 public，並加入簡短描述「黑客松團隊專案」。創建完成後，請告訴我如何在 GitHub 網頁上進入 Settings → Collaborators，把其他組員的 GitHub 帳號加入為協作者。

⚠️ 注意：請在執行前把以下指令中的 repo 名稱「hackathon-team」替換成你們團隊實際決定的名稱：
gh repo create hackathon-team --public --description "黑客松團隊專案"
⚠️ 「hackathon-team」只是範例名稱，請務必替換成你們團隊實際的 repo 名稱再執行。例如：gh repo create team-alpha-2025 --public --description "黑客松團隊專案"
所有組員任務（a → b → c）：認證 → Clone → 建立 Branch → Commit → Push
組員 = 除 Repo 創建者以外的所有團隊成員
  • Step a  確認並安裝 git 與 gh CLI，執行 gh auth login 透過瀏覽器完成 GitHub 認證
  • Step b  執行 git clone 將組長建立的 repo 複製到本地端
  • Step c  建立個人 branch，新增一個技能分享檔案後 commit，再 push 到 GitHub
組員 Step a  安裝 git 與 gh CLI，並透過瀏覽器完成 GitHub 認證 
請幫我依序完成以下兩件事：

1. 確認系統是否已安裝 git 和 gh CLI。如果尚未安裝，請依照我的作業系統給我安裝指令。

2. 安裝完成後，執行 gh auth login 並引導我完成 GitHub 認證，選項依序為：
   - GitHub.com
   - HTTPS
   - Authenticate Git with your GitHub credentials → Yes
   - Login with a web browser
   
瀏覽器開啟後我會登入並授權。完成後請執行 gh auth status 確認認證成功。
💡 每位組員在自己的電腦上各執行一次，設定完成後才能 clone 和 push。
組員 Step b  Clone 組長建立的 Repo 
請幫我 clone 以下 GitHub repo 到本地端，並進入該目錄：
git clone https://github.com/【組長帳號】/【repo名稱】.git
cd 【repo名稱】

clone 完成後，請顯示目前目錄內容（ls 或 dir）以及目前所在的 branch（git branch）。
⚠️ 請替換兩處佔位符再執行：「【組長帳號】」換成組長的 GitHub 帳號，「【repo名稱】」換成組長在 Step 3 建立的實際 repo 名稱。例如：git clone https://github.com/john123/team-alpha-2025.git
組員 Step c  建立 Branch、新增檔案、Commit 並 Push 
請幫我依序完成以下步驟：

1. 建立並切換到新 branch，命名規則為 feature/名字-角色：
   git checkout -b feature/【你的名字】-【你的角色】

2. 在這個 branch 新增一個技能分享檔案，檔名為 skill-【你的名字】.md，內容包含：
   - 你擅長的一項技能（例如：資料分析、簡報設計、文案撰寫、UI設計…）
   - 這個技能在黑客松中可以如何幫助團隊
   - 你願意在哪個環節貢獻這個技能

3. 將新檔案加入追蹤並 commit：
   git add .
   git commit -m "新增：【你的名字】技能分享"

4. 將 branch push 到 GitHub：
   git push origin feature/【你的名字】-【你的角色】

完成後請顯示 git log --oneline -3 確認 commit 已記錄。
💡 將 【你的名字】 和 【你的角色】 替換為實際內容，例如：feature/小明-視覺設計。技能分享檔案內容為公開可見，請勿填寫個人隱私資料。
GitHub 協作操作流程

從建立 repo 到整合，完整的 GitHub 協作步驟

  • 1
    派一位代表在 GitHub 上新增團隊 repo，並在 Settings → Collaborators 將所有其他成員加入協作者
  • 2
    其他成員收到邀請並接受後，在自己的電腦執行 git clone 將 repo 複製到本地：
    git clone https://github.com/帳號/repo名稱.git
  • 3
    每位成員進入 repo 目錄，依照自己的角色新增個人 branch，建議命名規則 feature/名字-角色：
    git checkout -b feature/名字-角色
  • 4
    每人確認自己的 branch 已完成最後一次 commit + push
  • 5
    向技術 Lead 發出 Pull Request，附上簡短說明（我做了什麼）
  • 6
    技術 Lead 審查並 merge 到 main，發現衝突時請 Bob 協助解決
  • 7
    所有人從 main pull 最新版本，確認本地端與 GitHub 同步
  • 8
    確認 GitHub repo 上每人都有 commit 紀錄，README 完整
