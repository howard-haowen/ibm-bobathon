COBOL 四大傳承任務實踐

我們將展示新進工程師如何透過 IBM Bob，將看似天書的 COBOL 程式碼快速轉化為可讀文件與新功能代碼。

任務一：解讀 (Deconstruct) — 看懂核心開單邏輯

當我們需要讀懂 LGACUS01.cbl 中的 CICS & DB2 變數映射時，可以貼出該 COBOL 段落，並使用 Ask 模式請求 Bob 解讀：

* COBOL CODE SAMPLE FROM LGACUS01.cbl
       EXEC CICS GET CONTAINER('Customer')
                 INTO(CUSTOMER-DATA)
                 RESP(WS-RESP)
       END-EXEC.
       
       IF WS-RESP = DFHRESP(NORMAL)
           MOVE CUSTOMER-ID TO DB-CUST-ID
           EXEC SQL
               INSERT INTO CUSTOMER (CUST_ID, FIRST_NAME, LAST_NAME)
               VALUES (:DB-CUST-ID, :DB-FIRST-NAME, :DB-LAST-NAME)
           END-EXEC
       ELSE
           PERFORM ERROR-HANDLING
       END-IF.
學員 Prompt (Ask 模式)
「請幫我用繁體中文解讀這段 COBOL 程式碼。這是一個 CICS 交易，請解釋它如何獲取資料，以及在什麼條件下會寫入 DB2 資料庫？」
IBM Bob 的分析回應
1. CICS 容器獲取：此段程式碼首先透過 EXEC CICS GET CONTAINER 指令，自名為 'Customer' 的容器中讀取學員/客戶資料，並將其放入 CUSTOMER-DATA 變數中，同時將狀態存入 WS-RESP。
2. 條件防呆校驗：只有當 WS-RESP 的回應為 DFHRESP(NORMAL)（即讀取完全正常）時，才會執行後續的 DB2 寫入。
3. DB2 SQL 寫入：將本地變數 CUSTOMER-ID 搬移（MOVE）至 DB-CUST-ID，並執行內嵌 SQL INSERT INTO CUSTOMER 寫入資料庫。
4. 異常處理：若讀取容器失敗，則進入 ERROR-HANDLING 錯誤處理段落。

任務二：文件化 (Document) — 萃取核心業務邏輯

核心系統最怕「人走茶涼、文件遺失」。我們可以使用 Bob 為 LGUPVS01.cbl 自動提煉出結構化的 Business Rules 文件：

學員 Prompt (Plan / Ask 模式)
「這段 COBOL 代碼包含理賠比例的限制：如果保單不滿一年，理賠金額上限為 50%，如果滿一年但小於三年則為 80%。請幫我以此萃取出一份繁體中文的業務規則規格書（Business Rules Specification）。」
IBM Bob 產生的文件草稿

理賠核心業務規則 (Rule-ID: INS-CLM-01)

1. 規則意圖：防止短期惡意投保理賠，並根據保單效期進行理賠額度遞增控管。

保單效期 (T) 理賠上限比例 對應 COBOL 控制變數
T < 1 年 50% WS-POLICY-AGE < 365
1 年 ≤ T < 3 年 80% WS-POLICY-AGE ≥ 365 AND < 1095
T ≥ 3 年 100% (全額) ELSE 段落

任務三與任務四：撰寫新段落與知識傳承

任務三：新進撰寫 (Construct)

當業務變更，需要增加一個「核對保單是否已逾期」的判斷段落時。新進工程師只需輸入商業邏輯：

Bob 產生的符合規格 COBOL 片段： 
       Evaluate True
           When Expiry-Date < Current-Date
               Set Policy-Status-Expired To True
               Perform Expired-Handling
           When Other
               Perform Normal-Processing
       End-Evaluate.

任務四：新進傳承 (Transfer)

系統交接給新進同仁時，讓 Bob 自動產生「新手工程師導覽卡」：

  • 變數命名法：WS- 開頭代表 Working Storage，LS- 代表 Linkage Section。
  • 交易調用：DFHRESP(NORMAL) 是 CICS 中檢查 API 執行成功的最常用手段。
  • 除錯技巧：利用 Bob 提煉出段落呼叫圖 (Paragraph Call Tree) 快速定位死循環。

Bob COBOL 傳承常用 Prompt 速查表

應用場景 推薦使用的對話範本 (Prompt)
代碼快速導讀 「請幫我產生這段 COBOL 程式碼的 Paragraph 呼叫順序，並指出最核心的入口 paragraph 哪裡？」
資料庫字典映射 「請列出這段 EXEC SQL 區塊中，所有的 Host Variables 及其對應的 DB2 資料庫欄位對照表。」
防呆與業務規則提煉 「這段程式碼有哪些防呆、例外處理（Exception Handling）與 Error Code？請用繁體中文條列成清單。」
現代化重構 (Java/API) 「如果我想把這段 COBOL 的開單核心邏輯用 Java Spring Boot 重寫，請幫我規劃資料結構與 RESTful API 的 JSON Payload 設計。」

常見問答

學員疑問 解答說明
我電腦沒有 Mainframe 模擬器也可以學這堂課嗎？ 完全可以。我們這堂課的重點在於「透過 IBM Bob 降低核心系統的理解門檻」，不依賴大型主機，利用 Bob 即可完成全套程式理解與重構。
Bob 如何處理大型、數萬行的 COBOL 檔案？ 您可以利用 Bob 的 GetSymbolsOverview 與 grep 工具，先找出核心的 Paragraph (段落)，並採取「精確切割、逐段解讀」的策略。
cics-genapp 的程式碼可以直接轉成 Java 嗎？ 可以使用 Bob 提供 Java 代碼架構的重寫指引。但通常建議先由 Bob 萃取出「純淨的業務規則」，再根據現代微服務架構重新設計。
