情境：為課程主題備課

IBM Bob 入門操作指南

Ask、Plan、Agent — 三種模式對應三種工作場景。以一個高中課程主題為起點，帶你走完從「搞懂主題」到「產出教案與教學網頁」的完整備課流程。不需要任何程式知識。

情境：下週要教新單元，想先備好一份教案

你是高二國文老師，下週要教一個新單元，想要一份能直接調整使用的教案、幾組能帶動課堂討論的提問，還有一個可以分享給學生的教學網頁。這正是 IBM Bob 教師備課助手的用武之地。以下為說明用的示例輸入，請換成你自己的課程。

三種模式一覽

確定課程主題後，正確的備課流程是依序切換三個模式，每個模式做它最擅長的事。

Ask

知識模式

釐清課程主題的概念、預想學生可能的學習難點、討論教學方向。不會修改任何檔案，適合在動手備課前先搞懂主題。

理解主題 解釋概念 預想難點 討論教法

權限：唯讀。不寫入本地檔案，不執行命令。

Plan

規劃模式

規劃教案結構、擬定教學目標、切分時間流程與活動。聚焦「教什麼、怎麼教」，在動手前確認方向。

教學目標擬定 時間流程切分 活動設計 提問方向規劃

權限：可讀取檔案，僅輸出計畫文字，不直接執行修改。

Agent

執行模式

根據規劃，先對照課綱，再自動產出差異化教案、啟發提問、摘要與宣傳文案，並搭建主題式教學網站（課程官網、活動宣傳頁或遊戲化互動專題）。

生成教案 設計提問 撰寫文案 產出 HTML

權限：完整讀寫，可呼叫工具、執行 Shell 命令。

實際演練

以上方的示例課程主題為起點，依序示範三個模式的正確用法。

TIP
在對話中輸入 @ 符號（例如 @檔案名稱 或 @資料夾名稱），即可快速將專案中的特定檔案或整個資料夾加入對話上下文，讓 Bob 直接讀取與分析目標內容。

Step 1 — Ask 模式

搞懂課程主題，確認教學起點

拿到課程主題，第一步不是馬上寫教案。先用 Ask 模式，把學科、年級與學生程度告訴 Bob，請它說明這個主題的核心概念、學生可能卡在哪裡，以及哪些內容適合先講。若你已有課本或講義檔案，可用 @檔案名稱 引用。Bob 的說明僅供參考，請依課本與你的專業判斷核對。

Prompt — Ask 模式 
我是高二國文老師，下週要教「赤壁賦：情景交融」，共 50 分鐘 × 2 堂，班級為一般程度。請先幫我說明這個主題的核心概念、學生可能的學習難點，以及哪些內容適合先講、哪些適合留給進階討論。請不要修改任何檔案。

Step 2 — Plan 模式

規劃教案的目標、時間流程與活動

Ask 模式已幫你掌握主題與學生難點。現在切換 Plan 模式，在動手產出教案之前，讓 Bob 規劃教學目標、時間流程與活動設計的草案。執行此步驟後，Bob 會在工作區產生一份結構化的規劃文件（一份規劃文件），供你在進入 Agent 模式前檢視確認。教學目標若由 Bob 擬定，會標示為「擬定，請教師確認」，最終由你決定。

Prompt — Plan 模式 
請幫我規劃上面這個單元的備課計畫，內容包含對應的課綱、教學目標、50 分鐘 × 2 堂的時間流程與活動設計、基礎與進階兩種程度的差異化做法、每個段落的啟發提問方向，以及最後要產出的教案與教學網站。請產出一份完整的規劃文件。
Bob 會回答的內容方向（示意）
✓ 產生一份結構化的規劃文件 ✓ 擬定教學目標草案，標示為「擬定，請教師確認」 ✓ 規劃時間流程：各段時間加總須等於 100 分鐘（50 分鐘 × 2 堂） ✓ 建議每個教學段落的活動，以及暖身、核心、延伸三層提問的方向 ✓ 說明基礎與進階兩種程度各自的目標、任務與支持方式 ✓ 說明會先查 108 課綱資料夾；找不到對應科目時會略過，並在規劃中註明 ✓ 規劃輸出目標：一份教案文件與一個教學網站 ✓ 僅產生/輸出計畫文件，不執行實際的教案生成或修改

Step 3 — Agent 模式

自動產出差異化教案，搭建教學網站

備課規劃已在 Plan 模式確認。切換至 Agent 模式，Bob 會依本專案的「工作說明書」（AGENTS.md）所定的工作流自動執行：課綱對照 → 差異化教案設計 → 啟發提問 → 摘要與宣傳文案 → 主題式網站。其中宣傳文案的對象與語氣、網站要做成哪一種類型，若你沒有指定，Bob 會先詢問你，不會自行假設。
