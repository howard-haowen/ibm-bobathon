IBM Bob 入門操作指南

本教材帶領您快速掌握 IBM Bob 的三大核心模式、Skill 安裝與 MCP Server 觀念，並透過實際對話範例，讓您在 10 分鐘內上手 AI 輔助開發。

IBM Bob 是什麼？

IBM Bob 是一個專為企業級軟體工程與維運設計的 Agent-native 開發助手。與通用型聊天 AI 相比，Bob 擁有更強的專案理解力、工具自動化執行能力與更嚴格的架構規範。

Mode 1

Plan 規劃模式

專注於分析複雜需求、架構設計或擬定步驟。在此模式下，Bob 會在不撰寫繁複代碼的前提下，幫助您列出技術規範、分析影響範圍與生成 ADR 文件。

Mode 2

Ask 知識模式

專門用來檢索知識、讀懂代碼，或查閱技術文件。適合在新進入一個 Codebase、解讀 COBOL 舊系統或排查日誌錯誤時使用，此模式不會隨意修改您的本地檔案。

Mode 3

Agent 執行模式

具備完整代碼編輯、命令執行、工具呼叫等高權限功能。當規劃與觀念確定後，切換至此模式可讓 Bob 自動為您修改程式碼、建立檔案與執行本地測試。

IBM Bob 核心觀念

在使用 Bob 時，您會經常接觸到三個核心名詞，了解它們能讓您的對話事半功倍：

名詞 核心含意 在工作坊中的實際用途
Mode (模式) 設定 AI 的行為守則與可用工具集。 防止 AI 在您只想問問題時隨意修改您的程式碼，提升安全與效率。
Skill (技能) 一組可重複使用的特定工作流與專業指導原則。 讓 Bob 立即載入「COBOL 萃取」、「Ansible 撰寫」等特殊領域的專家知識。
MCP Server Model Context Protocol 伺服器，連接外部工具與資料源。 讓 Bob 能夠直接讀取 Excel、檢索 Obsidian 知識庫或查詢本地開發環境。

快速上手：你的第一個 AI 對話

接下來，我們將模擬一個常見的開發任務：向 Bob 描述需求、生成一份專案報告，並將其轉換成 HTML 頁面。

01

分析需求 (Plan 模式)

首先將模式切換至 Plan，向 Bob 詢問：「我想做一個 AI 應用的簡報報告，請幫我規劃報告大綱與包含的章節。」

# 提示詞範例
我目前需要設計一份關於 IBM Bob 核心價值的報告，請幫我規劃包含三大核心痛點的大綱。
02

產生報告內容 (Agent 模式)

對大綱滿意後，切換至 Agent 模式，讓 Bob 直接在本地建立 Markdown 檔案。

# 提示詞範例
請在本地建立 artifacts/report.md，並將剛才規劃的三大核心痛點大綱，擴寫成完整的繁體中文內容。
03

轉換報告為 HTML

利用專案中已安裝的 markdown-to-html 技能，讓 Bob 一次性將報告渲染成符合 Carbon 風格的 HTML。

# 提示詞範例
請激活 markdown-to-html 技能，將 report.md 轉換成 report.html，並使用 Carbon Design System 的極簡無陰影樣式。

專業提示 (Pro Tip)

一次只做一件事

在使用 Agent 模式時，建議將複雜的任務拆解成多個小對話。先用 Plan 模式進行架構確認，再用 Agent 模式寫代碼，最後在 Ask 模式下進行程式碼重構與複審，這能保證最高的生成品質。

常見問答

常見問題 解答說明
為什麼 Bob 拒絕幫我修改程式碼？ 請檢查您目前的模式。如果是處於 Ask 或 Plan 模式，Bob 會被安全規範限制，無法寫入檔案。請在對話中輸入「切換至 Agent 模式」或使用工具列切換。
Bob 產生的 HTML 為什麼沒有圓角？ 這是 IBM Carbon Design System 的規範。Carbon 強調絕對的扁平與幾何精密，因此按鈕、輸入框、卡片皆採用 0px 圓角與無陰影（No Shadow）設計。
需要連線上網才能使用 Bob 嗎？ Bob 本身是 Agent，雖然模型推理需要連線，但在讀取本地 Excel、執行 CLI 編譯與檔案編輯時，皆是在您的本地端（Localhost）安全執行。
如何確保 Bob 不會動到我不相干的檔案？ Bob 在執行關鍵變更前會先向您確認。此外，請保持 Git 工作樹乾淨，您隨時可以使用 Git Commit 或 Git Stash 來管理與還原變更。
