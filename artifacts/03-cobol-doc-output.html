第五章：程式流程與控制

MAINLINE SECTION 流程：

1. INITIALIZE WS-HEADER
2. ACCEPT 環境變數（GENAPP_TRANSID / GENAPP_TERMID / GENAPP_TASKNUM）
3. IF DFHCOMMAREA = SPACES → WRITE-ERROR-MESSAGE + STOP RUN
4. MOVE '00' TO CA-RETURN-CODE / CA-NUM-POLICIES
5. COMMAREA 長度驗證：WS-CA-HEADER-LEN(18) + WS-CUSTOMER-LEN(72) = 90
   IF LENGTH OF DFHCOMMAREA < 90 → CA-RETURN-CODE='98' + GOBACK
6. PERFORM CHECK-FIRST
   IF WS-RESPONSE-CODE > 0 → CA-RETURN-CODE = WS-RESPONSE-CODE + GOBACK
7. PERFORM FRAUD-CHECK
   IF WS-STATUS NOT = 'valid' → CA-RETURN-CODE='81' + GOBACK
8. PERFORM INSERT-CUSTOMER
   IF CA-RETURN-CODE > 0 → GOBACK
9. GOBACK

CHECK-FIRST-COBOL 郵遞區號驗證邏輯：

  • 接受前綴：GB、US、UK、DN（大小寫不分）
  • 不符合 → WS-RESPONSE-CODE = '82'

WRITE-ERROR-MESSAGE 機制：

  1. ACCEPT WS-DATE FROM CENTURY-DATE（YYYYMMDD）
  2. ACCEPT WS-TIME FROM TIME（HHMMSSss）
  3. 填入 ERROR-MSG 各欄位（日期、時間、程式名 'LGACUS01'、客戶號、訊息）
  4. CALL 'LGSTSQ' USING BY REFERENCE ERROR-MSG
  5. MOVE DFHCOMMAREA(1:90) TO CA-DATA
  6. CALL 'LGSTSQ' USING BY REFERENCE CA-ERROR-MSG

第五章：程式流程與控制

1. INITIALIZE WS-HEADER + DB2-OUT-INTEGERS
2. ACCEPT 環境變數
3. IF DFHCOMMAREA = SPACES → STOP RUN
4. COMMAREA 長度驗證 (18+72=90)
5. PERFORM Obtain-CUSTOMER-Number
   ├── IF GENA-CUSTOMER-COUNTER = 0 → LGAC-NCS='NO'（使用 DEFAULT）
   └── ELSE → LastCustNum = 計數器值，計數器加 1
6. PERFORM INSERT-CUSTOMER
   ├── IF LGAC-NCS='ON' → INSERT 指定 DB2-CUSTOMERNUM-INT
   └── ELSE → INSERT DEFAULT → SET DB2-CUSTOMERNUM-INT = IDENTITY_VAL_LOCAL()
7. MOVE DB2-CUSTOMERNUM-INT TO CA-CUSTOMER-NUM
8. CALL 'LGACVS01' USING BY REFERENCE DFHCOMMAREA RETURNING WS-DB-RETURN-CODE
9. 準備 CDB2AREA（D2-CUSTOMER-NUM, D2-REQUEST-ID='02ACUS', 預設密碼）
10. CALL 'LGACDB02' USING BY REFERENCE CDB2AREA RETURNING WS-DB-RETURN-CODE
11. GOBACK

批次 FETCH 流程（以 GET-COMMERCIAL-DB2-INFO-3 為例）：

1. MOVE 0 TO ICOM-RECORD-COUNT
2. EXEC SQL OPEN Cust_Cursor END-EXEC
   IF SQLCODE ≠ 0 → RC='89' + WRITE-ERROR-MESSAGE
3. PERFORM GET-COMMERCIAL-DB2-INFO-3-CUR WITH TEST AFTER UNTIL SQLCODE > 0
   每次 FETCH：
   a. EXEC SQL FETCH Cust_Cursor INTO :DB2-* ... END-EXEC
   b. IF SQLCODE = 0：
      - 整數欄位轉換（DB2-B-*-Int → DB2-B-*）
      - ADD 1 TO ICOM-RECORD-COUNT
      - MOVE DFHCOMMAREA(1:1202) TO ICOM-RECORD（最新一筆覆蓋緩衝區）
      - IF ICOM-RECORD-COUNT > 20 → MOVE 17 TO SQLCODE（強制停止）
4. EXEC SQL CLOSE Cust_Cursor END-EXEC
   IF SQLCODE ≠ 0 → RC='88' + WRITE-ERROR-MESSAGE

⚠️ 注意：ICOM-RECORD 為 1202 bytes 單筆緩衝區，批次 FETCH 時每筆都會覆蓋同一緩衝區。呼叫端（LGIPOL01）只能取得最後一筆資料，ICOM-RECORD-COUNT 記錄總筆數。最多 20 筆（超過後以 MOVE 17 TO SQLCODE 強制結束迴圈）。

4. 從 COMMAREA 取得搜尋前綴：

第 5 章：程式流程

MAINLINE SECTION 流程：

1. INITIALIZE WS-HEADER / DB2-POLICY / DB2-IN-INTEGERS
2. ACCEPT 環境變數（TRANSID/TERMID/TASKNUM）
3. IF DFHCOMMAREA = SPACES → STOP RUN
4. MOVE CA-CUSTOMER-NUM TO DB2-CUSTOMERNUM-INT
   MOVE CA-POLICY-NUM   TO DB2-POLICYNUM-INT
5. PERFORM UPDATE-POLICY-DB2-INFO（主要邏輯）
6. CALL 'LGUPVS01' USING BY REFERENCE DFHCOMMAREA RETURNING WS-DB-RETURN-CODE
7. GOBACK

UPDATE-POLICY-DB2-INFO 六步驟流程（樂觀鎖定）：

步驟 1: OPEN POLICY_CURSOR
        EVALUATE SQLCODE
          WHEN 0   → 繼續
          WHEN -913 → RC='02'（死鎖）WRITE-ERROR-MESSAGE + GOBACK
          WHEN OTHER → RC='90' WRITE-ERROR-MESSAGE + GOBACK

步驟 2: PERFORM FETCH-DB2-POLICY-ROW
        FETCH POLICY_CURSOR INTO :DB2-ISSUEDATE, :DB2-EXPIRYDATE,
              :DB2-LASTCHANGED, :DB2-BROKERID-INT, :DB2-BROKERSREF, :DB2-PAYMENT-INT

步驟 3: IF SQLCODE = 0（找到記錄）
          IF CA-LASTCHANGED = DB2-LASTCHANGED（版本戳相符）
            EVALUATE CA-REQUEST-ID
              WHEN '01UEND' → PERFORM UPDATE-ENDOW-DB2-INFO
              WHEN '01UHOU' → PERFORM UPDATE-HOUSE-DB2-INFO
              WHEN '01UMOT' → PERFORM UPDATE-MOTOR-DB2-INFO
          ELSE（版本戳不符）
            RC='02'（樂觀鎖失敗）

步驟 4: IF 子表 UPDATE 成功
          MOVE CA-BROKERID TO DB2-BROKERID-INT
          MOVE CA-PAYMENT  TO DB2-PAYMENT-INT
          UPDATE POLICY SET ISSUEDATE, EXPIRYDATE, LASTCHANGED=CURRENT TIMESTAMP,
                            BROKERID, BROKERSREFERENCE
            WHERE CURRENT OF POLICY_CURSOR

步驟 5: SELECT LASTCHANGED INTO :CA-LASTCHANGED
          FROM POLICY WHERE POLICYNUMBER = :DB2-POLICYNUM-INT
        IF SQLCODE ≠ 0
          → EXEC SQL ROLLBACK END-EXEC
          → RC='90'

步驟 6: PERFORM CLOSE-PCURSOR

CLOSE-PCURSOR 特殊處理：

SQLCODE 處理 說明
0 RC='00' 正常關閉
-501 RC='00' + GOBACK 游標未開啟（可忽略）
OTHER RC='90' + WRITE-ERROR-MESSAGE + GOBACK —

第 5 章：程式流程

MAINLINE SECTION 流程（文字描述）：

1. MOVE LENGTH OF DFHCOMMAREA TO WS-Commarea-Len
2. ACCEPT WS-KSDSPOLY-PATH FROM ENVIRONMENT 'GENAPP_KSDSPOLY'
   IF = SPACES → MOVE '/tmp/KSDSPOLY' TO WS-KSDSPOLY-PATH（預設路徑）
3. 組裝複合鍵：
   MOVE CA-Request-ID(4:1) TO WF-Request-ID（取第 4 個字元：E/H/M/C）
   MOVE CA-Policy-Num      TO WF-Policy-Num
   MOVE CA-Customer-Num    TO WF-Customer-Num
4. EVALUATE WF-Request-ID（保單類型 → 複製對應欄位至 KSDSPOLY-RECORD）
   WHEN 'C' → B-Postcode, B-Status, B-Customer
   WHEN 'E' → E-WITH-PROFITS, E-EQUITIES, E-MANAGED-FUND, E-FUND-NAME, E-LIFE-ASSURED
   WHEN 'H' → H-PROPERTY-TYPE, H-BEDROOMS, H-VALUE, H-POSTCODE, H-HOUSE-NAME
   WHEN 'M' → M-MAKE, M-MODEL, M-VALUE, M-REGNUMBER
   WHEN OTHER → MOVE SPACES TO WF-Policy-Data
5. MOVE CA-Policy-Num TO WF-Policy-Num（二次覆寫，確保正確）
6. OPEN I-O KSDSPOLY-FILE
   IF 失敗 → RC='81' + WRITE-ERROR-MESSAGE + STOP RUN
7. READ KSDSPOLY-FILE WITH LOCK
   IF 失敗 → RC='81' + WRITE-ERROR-MESSAGE + CLOSE + STOP RUN（ABCODE=LGV3）
8. REWRITE KSDSPOLY-RECORD
   IF 失敗 → RC='82' + WRITE-ERROR-MESSAGE + CLOSE + STOP RUN（ABCODE=LGV4）
9. CLOSE KSDSPOLY-FILE
10. GOBACK

第 5 章：程式流程

主流程（0001-MAIN）：

1. DISPLAY 'START OF PROGRAM'
2. PERFORM 1000-INITIALIZATION THRU 1000-EXIT
   → INITIALIZE WS-SWITCHES
   → OPEN INPUT INPUT01-FILE（失敗 → 9000-END-PARA）
3. PERFORM 1500-READ-INPUT THRU 1500-EXIT
   → READ INPUT01-FILE INTO WS-IN-REC AT END SET END-OF-INP TO TRUE
4. IF NOT END-OF-INP
   → PERFORM 2000-MAIN-PARA THRU 2000-EXIT
     → INITIALIZE DCLCUSTOMER
     → MOVE IN-CUST-* TO DCL-*（10 個欄位）
     → PERFORM 3000-INS-CUST-DETAILS THRU 3000-EXIT
       → EXEC SQL INSERT INTO CUSTOMER (...) VALUES (...) END-EXEC
       → DISPLAY 'SQLCODE:' SQLCODE
       → EVALUATE SQLCODE
           WHEN 0 → DISPLAY 'SUCCESSFUL INSERT'
           WHEN OTHER → WS-STATUS-CODE = 0001 + DISPLAY + 9000-END-PARA
5. PERFORM 9000-END-PARA
   → GOBACK

原始 IBM z/OS 版本中，LGCMAREA 透過 EXEC CICS LINK 的 COMMAREA 機制自動傳遞。 轉置後改為 CALL 'PROGRAM' USING BY REFERENCE DFHCOMMAREA，由呼叫端將 DFHCOMMAREA 宣告並傳入，被呼叫端以 PROCEDURE DIVISION USING BY REFERENCE DFHCOMMAREA 接收。原 EIBCALEN 改為 LENGTH OF DFHCOMMAREA 判斷長度。

第十一章：錯誤處理

  • 各程式於 MAINLINE 開頭均驗證：IF DFHCOMMAREA = SPACES → 呼叫 LGSTSQ 記錄錯誤後 STOP RUN
  • 各 DB2 層程式另驗證：IF LENGTH OF DFHCOMMAREA < WS-REQUIRED-CA-LEN → 設定 CA-RETURN-CODE = '98' 後 GOBACK

第十三章：資料契約

  • 輸入方向（呼叫端 → 被呼叫端）：CA-REQUEST-ID、CA-CUSTOMER-NUM、各 REDEFINES 對應欄位
  • 輸出方向（被呼叫端 → 呼叫端）：CA-RETURN-CODE（必填）、查詢操作時回填各資料欄位
  • 共用記憶體語義：BY REFERENCE 傳遞，被呼叫端對 DFHCOMMAREA 的修改對呼叫端立即可見
