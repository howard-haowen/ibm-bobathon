用 IBM Bob 輔助 WAS、MQ、Db2 維運與 Ansible 自動化

本教材展示如何利用 IBM Bob 的 Ask 與 Agent 模式，在不依賴真實伺服器的情況下，進行 WAS/MQ 錯誤日誌分析、Db2 SQL 問題排查，並自動生成 Ansible 自動化 Playbook。

維運四大實戰情境

在大型企業中，維運工程師每天面對無數的系統日誌與繁瑣的重啟任務。IBM Bob 可扮演您的維運副駕駛，在關鍵時刻提供秒級診斷建議與腳本支援：

WAS 日誌診斷

快速解讀 SystemOut.log 的 Java OutOfMemory 堆疊，提供故障排除與參數優化方案。

MQ 通道排查

定位 AMQ 錯誤代碼，分析網路與認證失敗原因，無需翻閱厚重的系統指南。

Db2 SQL 輔助

描述系統異常需求（如死鎖、長時間等待），由 Bob 即時生成精確的診斷型 SQL 語法。

Ansible 自動維護

自動生成標準化 Playbook，快速分發配置或重啟損壞節點，降低手動操作失誤。

情境一：WAS SystemOut.log 分析

當 WebSphere Application Server 突然當機，而日誌中噴出以下 JVM OutOfMemory 片段時，新進維運同仁往往不知從何下手：

JVM SystemOut.log EXCERPT
[10/24/23 15:42:01:294 CST] 0000004d SystemErr R Exception in thread "WebContainer : 3" java.lang.OutOfMemoryError: Java heap space at java.util.Arrays.copyOf(Arrays.java:3332) at java.io.ByteArrayOutputStream.write(ByteArrayOutputStream.java:167) at com.ibm.ws.webcontainer.srt.impl.HttpInputStream.read(HttpInputStream.java:214)
學員 Prompt (Ask 模式)
「請幫我診斷這段 WAS 日誌。發生了什麼問題？我該如何排查，以及在 WAS 主控台需要調整哪些參數？」
IBM Bob 的維運診斷回應
1. 根本原因：JVM 堆疊記憶體不足（java.lang.OutOfMemoryError: Java heap space），這意味著應用程式耗盡了分配給 WAS JVM 的記憶體。
2. 代碼層分析：從堆疊軌跡可以看出，在處理 HttpInputStream.read 並往 ByteArrayOutputStream 寫入大檔案時發生了擴容拷貝（Arrays.copyOf），推測是學員/使用者上傳了超大型檔案。
3. 應急排查法：使用 IBM Memory Analyzer (MAT) 分析 .phd 或 .hprof 格式的 Heap Dump，找出記憶體洩漏（Memory Leak）的主要物件。
4. 主控台參數調整：登入 WAS 管理主控台 Servers > Server Infrastructure > Java and Process Management > Process definition > Java Virtual Machine，將 "Maximum heap size"（最大堆疊記憶體，例如由 1024M 擴增至 2048M）適度上調。

情境二：IBM MQ AMQERR01.LOG 分析

當 MQ Channel 無法正常啟動，連線發生異常時，AMQ 錯誤日誌是關鍵的線索來源：

MQ AMQERR01.LOG EXCERPT
AMQ9208E: Error on receive from host '192.168.1.105 (192.168.1.105)'. EXPLANATION: An error occurred receiving data from '192.168.1.105 (192.168.1.105)' over TCP/IP. ACTION: The connection to the remote host was unexpectedly terminated. Record the TCP/IP error code 10054 (X'2746').
學員 Prompt (Ask 模式)
「我的 MQ 通道斷開了，AMQ9208E 伴隨錯誤碼 10054 代表什麼意思？我該如何修復它？」
IBM Bob 的維運診斷回應
1. 錯誤解讀：AMQ9208E 是典型 TCP/IP 通訊層錯誤。而 Windows TCP/IP 錯誤碼 10054 (或 Linux 下的 ECONNRESET) 代表「連線被遠端主機強行關閉」。
2. 常見肇因：遠端的佇列管理器（Queue Manager）突然重啟、遠端的 MQ 監聽器（Listener）沒在運行，或者介於兩台主機之間的防火牆（Firewall）因為閒置逾時（Idle Timeout）強行切斷了 TCP 長連線。
3. 排查步驟：
   • 檢查遠端 MQ 主機，確保 runmqlsr -m QM_NAME -p 1414 正在正常監聽。
   • 檢查 MQ Channel 的 KeepAlive 屬性。在佇列管理器端設置 KeepAlive=YES，利用 TCP 保活機制防止防火牆隨意中斷閒置連線。

情境三：Db2 維運 SQL 生成

當核心資料庫效能低下、疑似發生死鎖等待（Lock Wait）時，我們可以描述需求，讓 Bob 自動產生專屬的診斷 SQL 語法：

學員 Prompt (Agent 模式)
「請幫我寫一條 IBM Db2 語法，用來查詢目前所有正在處於 Lock Wait 狀態的 Application Handle、鎖定的 Table 名稱以及等待的時間（秒數）。」
IBM Bob 生成的 Db2 診斷 SQL
SELECT 
    AI.AGENT_USERID AS USER_ID,
    LW.AGENT_HOLDING_LK AS LOCK_HOLDER_HANDLE,
    LW.REQ_AGENT_ID AS WAITING_HANDLE,
    LW.LOCK_NAME AS LOCK_ID,
    LW.TABNAME AS TABLE_NAME,
    LW.LOCK_WAIT_START_TIME AS START_TIME,
    (CURRENT TIMESTAMP - LW.LOCK_WAIT_START_TIME) AS WAIT_TIME_SECONDS
FROM 
    SYSIBMADM.LOCKWAITS LW
JOIN 
    SYSIBMADM.APPL_INFO AI ON LW.REQ_AGENT_ID = AI.AGENT_ID
ORDER BY 
    WAIT_TIME_SECONDS DESC;

情境四：Ansible 自動重啟 WAS Playbook 生成

診斷完畢後，若需要將「重啟 WAS 伺服器」的繁瑣步驟寫入自動化運維流程中，我們可以直接讓 Bob 自動草稿一份標準的 Ansible Playbook：

# Ansible Playbook 示範 (由 Bob Agent 模式生成)
- name: Restart WebSphere Application Server Node
  hosts: was_servers
  become: yes
  vars:
    was_profile_path: "/opt/IBM/WebSphere/AppServer/profiles/AppSrv01/bin"
    was_server_name: "server1"

  tasks:
    - name: Stop WebSphere Application Server
      shell: "./stopServer.sh {{ was_server_name }} -username admin -password admin_pwd"
      args:
        chdir: "{{ was_profile_path }}"
      ignore_errors: yes

    - name: Ensure JVM process is dead
      wait_for:
        port: 9080
        state: stopped
        timeout: 30

    - name: Start WebSphere Application Server
      shell: "./startServer.sh {{ was_server_name }}"
      args:
        chdir: "{{ was_profile_path }}"

    - name: Verify server port is listening
      wait_for:
        port: 9080
        delay: 5
        timeout: 120

常見問答

學員疑問 解答說明
Bob 判斷錯誤碼是否可能過時或不準？ Bob 使用最先進的檢索機制。對於 IBM 這種擁有高穩定度的產品（WAS/MQ），其 SystemOut、AMQ 錯誤代碼數十年來皆保持高度向下相容，診斷準確度極高。
我可以讓 Bob 直接幫我執行 Ansible Playbook 嗎？ 只要在 Agent 模式下，且您的本機具備 ansible-playbook 執行環境，並且 Bob 被授予了對應的 CLI 執行權限，Bob 即可直接幫您呼叫指令測試。
為什麼在 Db2 中我的診斷 SQL 找不到對應的表？ 請確認您的 Db2 版本與環境配置。部分效能視圖需要開啟監控器開關（例如：db2 update dbm cfg using DFT_MON_LOCK ON）才能正常獲取鎖資訊。
