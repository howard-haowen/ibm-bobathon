## Finding ID: CX-2025-0714-001

| Field | Value |
|---|---|
| **Category** | Incomplete Transaction (CWE-841) |
| **Severity** | Critical |
| **File** | `src/main/java/com/ibm/banking/service/TransactionService.java` |
| **Location** | Method `transfer(String, String, BigDecimal)`, lines 25–68 |

### Vulnerability Description

Transfer operation deducts funds from the source account (`sourceAccount.setBalance(newSourceBal)`) but does not query, validate, or update the target account balance. Furthermore, no transaction boundary or rollback mechanism is present in the failure path.

The transaction is left in an inconsistent partial state: funds are debited from the sender but never credited to the receiver. **High risk of financial loss and data inconsistency.**

### Code Snippet

```java
// Line 46-54 in TransactionService.java
BigDecimal newSourceBal = sourceAccount.getBalance().subtract(amount);
sourceAccount.setBalance(newSourceBal);
accountRepository.save(sourceAccount);

// [FINDING] Target account balance is never queried or credited!
// Target account update and error rollback are missing.

accountRepository.logTransaction(...);
return TransactionResult.success("TRANSFER COMPLETED");
```

### Remediation Guidance

1. Query and validate the target account (`findByAccountNumber(targetAccountNo)`).
2. Validate that the target account status is `ACTIVE`.
3. Credit the amount to the target account and persist changes.
4. Ensure atomicity: if the target account validation or credit fails, rollback the source account deduction.
